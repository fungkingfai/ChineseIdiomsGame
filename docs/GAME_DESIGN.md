## 1. 遊戲概念

**一句話**：跟住黑貓店長阿墨同橘虎斑小貓糰子，喺二十個貓貓場景收集「成語靈珠」——用填字同接龍兩種玩法，逐關解鎖 **200 個**成語填字／接龍謎題（基礎篇 Level 1–100＋進階篇 Level 101–200）。

- **類型**：單機益智（成語填字／接龍）＋收集＋輕敘事。
- **平台**：靜態 SPA（Vite + TypeScript，無框架、無 runtime 依賴、無外部網路請求）。
- **語言**：繁體中文（香港用語）；程式識別名英文。
- **目標玩家**：小學生至中學生、家長陪玩、喜歡貓貓同文字遊戲嘅一般玩家。
- **一局時間**：每關約 1–3 分鐘；一章 10 關約 15–30 分鐘。
- **核心賣點**：
  1. **貓貓世界觀**：阿墨（冷靜博學）＋糰子（好奇好動）沿途互動，十個場景各有氣氛。
  2. **兩種玩法交替**：填字（十字交叉）＋接龍（首尾相連），節奏有變化。
  3. **逐個成語自動判定**：填啱一句即刻鎖定、變綠、貓貓開心；填錯震動清空、貓貓傷心，feedback 直接。
  4. **零壓力收集**：過關即收入成語圖鑑（釋義、拼音、出處、例句），重玩取最高星。
  5. **手機優先**：單手可玩、無橫向 scroll、離線可用。

### 1.1 非目標（Non-goals）

- 唔做即時對戰、排行榜、帳號系統、雲端存檔。
- 唔做課金／廣告／外部字體／外部圖片。
- 唔做自由輸入（玩家只由字庫揀字，避免輸入法／異體字問題）。
- 唔做每日任務等營運功能（可列未來擴展，見 §17）。

## 2. 世界觀與角色

### 2.1 世界觀

貓貓世界有一座藏在十個場景之間嘅「成語私塾」。傳說每當有人正確讀出一句成語，天上就會多亮一顆星；十個場景各有一顆**成語靈珠**，靈珠吸收住該處流傳嘅成語智慧。某日靈珠四散、字句散落各處，店長貓阿墨帶住小貓糰子出發，逐章把靈珠收集返嚟，最後登上「成語之巔」。

- **敘事單位**：每一章＝一個場景（10 關）；每章第一次進入顯示章節故事卡；每關有 1–2 句貓貓小故事；每章第 10 關係「章末考驗」。
- **兩篇結構**：Level 1–100＝基礎篇（第 1–10 章，v1.1 內容不變，Level 100 為基礎篇結局）；Level 101–200＝進階篇（第 11–20 章，更冷僻成語／更大棋盤／更長接龍，Level 200 為全遊戲最終結局）。
- **敘事語氣**：溫暖、幽默、口語化香港繁體中文；阿墨負責講解，糰子負責發問／搞氣氛。唔用說教式長篇大論，故事只做情境同動機，唔穿橋答案。

### 2.2 角色

| 角色 | 設定 | 遊戲內功能 |
| --- | --- | --- |
| **阿墨**（amo） | 黑貓店長，冷靜博學，綠圍巾；成語私塾主人 | 旁白／提示語氣；填字成功時點頭；錯誤時無奈但溫柔 |
| **糰子**（dango） | 橘虎斑小貓，好動好奇，粉圍巾；阿墨嘅徒弟 | 玩家代入角色；成功時開心跳起、錯誤時垂耳、提示時「諗緊」表情 |

貓貓表情對應（見 ART_DESIGN）：`idle`（待機呼吸）、`happy`（填啱）、`sad`（填錯）、`think`（提示／思考）、`celebrate`（過關）、`wink`（彩蛋）、`sleep`（閒置一段時間）。

## 3. 核心循環

```text
首頁（繼續第 N 關）
  └─▶ 關卡地圖（20 章：基礎篇 10＋進階篇 10）
        └─▶ 進入關卡（首次教學／章節故事 overlay）
              └─▶ 棋盤＋字庫：逐個成語填字／接龍
                    ├─ 正確 → 該成語鎖定（綠、音效、貓貓開心）
                    ├─ 錯誤 → 震動、清空該成語、mistakes+1、貓貓傷心
                    └─ 提示 → 隨機揭示一格（有限次）
              └─▶ 全部成語完成 → 過關 overlay
                    ├─ 星星（依錯誤／提示計）
                    ├─ 本關成語卡（拼音、釋義、出處）
                    ├─ 「下一關」／「再玩一次」／「返回地圖」
                    └─ 成語自動收入圖鑑、解鎖下一關
        └─▶ 圖鑑：翻看已收集成語
        └─▶ 設定：音效、減少動態、重置進度
```

設計原則：

- **短回合**：一關 2–6 個成語，完成時間 1–3 分鐘，適合碎片時間。
- **即時回饋**：每完成一句即判定，唔需要等全關完成先知對錯。
- **低懲罰**：錯誤只清空該句、不扣星（只影響星級），提示亦只影響星級；永不卡死。
- **進度可見**：地圖顯示每關星星、每章進度、總星數；首頁永遠有「繼續」入口。

## 4. 關卡模式規則

200 關分兩種模式：**fill（填字）** 同 **chain（接龍）**。

### 4.1 模式分佈

| 模式 | 關卡 | 數量 | 規則 |
| --- | --- | --- | --- |
| `fill` 填字 | 除以下 chain 關以外全部 | **162 關**（基礎 82＋進階 80） | 基礎 2–4／進階 4–5 個成語以十字交叉方式排列，部分字空格，由字庫揀字填入 |
| `chain` 接龍 | `id >= 11 && id % 5 === 0`：15、20、…、100 及 105、110、…、200 | **38 關**（基礎 18＋進階 20） | 基礎 3–6／進階 6–7 個成語首尾相接（上一句尾字＝下一句首字），直向排列 |

- Level 1–10（第 1 章）全部 `fill`：教學期，唔加接龍負擔。
- 第 2–10 章及第 11–20 章每章有 2 關 `chain`：該章第 5 關（中段挑戰）＋第 10 關（章末考驗）。
- 第 10 章第 10 關（Level 100）＝基礎篇結局（chain 6 句）；第 20 章第 10 關（Level 200）＝全遊戲最終考驗（chain 7 句）。
- 進階篇（第 11–20 章）規則差異見 §19.2。

### 4.2 fill（填字）規則

**盤面**

- 棋盤係 `rows × cols` 方格，「有字格」定義喺 `level.cells`；冇字格唔顯示內容。
- 每個成語係一個 `slot`：起始 `(row, col)`＋方向 `h`（橫向，向右）或 `v`（直向，向下），固定 4 字。
- 一個成語佔 4 格；兩個成語「交叉」＝共用同一格，該格只有一個解答字，兩句喺嗰個位置嘅字必須相同。
- 生成器規則（寫入資料契約）：
  1. 每個 fill 關 2–4 個成語；
  2. **每個新成語必須同前面至少一個成語共用一格**（每個新字至少一次交叉）；
  3. 交叉位答案字必須一致；
  4. 盤面必須同時有橫向同直向成語（避免出現 1×7 直線盤面）；
  5. 盤面上限 9×9（極端資料 fallback 最多 11×11）；
  6. 每句保留 1–3 個空格（即每句最少 1 個「given」提示字、最多 3 個空格），避免全句空白或全句顯示。

**given 與 blank**

- `cells` 係全部有字格嘅解答字。
- `slot.blanks` 列出該成語第 1–4 個字（0-based）之中要玩家填嘅位置。
- **全域空格集合**＝所有 slot blanks 嘅聯集（同一格喺兩句都係空白時只算一個空格、只需一張字卡）。
- 冇被列為空格嘅格＝given：一開始已顯示、已鎖定、唔可以改。

**例子（Level 1，最終資料）**

```text
風花雪[月]   ← 橫向：風花雪月（blanks = [3] → 填「月」）
· ·[中]·    ← 直向：雪中送炭（row0 col2 起，同「雪」交叉，blanks = [1] → 填「中」）
· · 送 ·
· · 炭 ·
```

- 兩句喺「雪」字交叉；玩家由字庫 `[中, 月]` 揀字，填好一句即自動判定並鎖定。
- Level 1 只有兩個空格，配合教學 overlay，教「點格 → 點字卡 → 自動判定」三次動作。

**可解性**

- 解答由 `cells` 唯一決定；`bank` 係 multiset，每個空格字嘅數量一定足夠（同一字多格就多張卡）。
- 每句最少一個空格 → 引擎一定會喺玩家填字後觸發判定同鎖定（唔會出現「全顯示但永遠唔鎖定」）。

### 4.3 chain（接龍）規則

**盤面**

- `rows = 成語數 k`、`cols = 4`；第 i 行（0-based）＝第 i 個成語，`row = i, col = 0, dir = "h"`。
- 接龍條件：第 i 句嘅**尾字**（index 3）＝第 i+1 句嘅**首字**（index 0）。
- 每行係獨立一格棋盤，行與行之間唔會共用格；但相鄰兩行嘅「尾字—首字」係同一個字、各有一張字卡，視覺上用連接線／箭頭表示接龍關係。

**顯示／空格規則**（固定，見 PLAN §5.3）

| 行 | 保留顯示（given） | 可以空格 |
| --- | --- | --- |
| row 0（第一句） | 全句 4 字 | 冇（`blanks = []`，引擎建立遊戲時自動鎖定） |
| row i（`1 ≤ i ≤ k-2`，中段） | index 0（首字）＋ index 3（尾字） | index 1、2（最多 2 格） |
| row k-1（最後一句） | index 0（首字） | index 1、2、3（最多 3 格） |

- 保留首／尾字嘅原因：玩家一定睇得到「上一句尾字＝下一句首字」，接龍關係唔會斷；row 0 全顯示等玩家有一句完整 anchor，明白題型。
- 因此 chain 關嘅空格比例有結構上限（k=3 最多 5/12、k=4 最多 7/16、k=5 最多 9/20、k=6 最多 11/24，見 LEVEL_DESIGN），難度主要靠成語數、tier、誘餌字、提示次數遞增。

**例子（Level 15，最終資料）**

```text
夜郎自大        ← 全顯示（row 0）
大[快]人心      ← 首字「大」、尾字「心」顯示；blanks [1] → 填「快」
心[曠][神][怡]  ← 首字「心」顯示；blanks [1,2,3] → 填「曠神怡」
```

字庫：`[神, 而(誘餌), 快, 曠, 怡]`；玩家要由 5 張卡揀 4 張放啱位。

### 4.4 兩種模式嘅共同規則

- 每關至少 2 個成語（fill 2–4、chain 3–6）。
- 每關至少有一個 **tier ≤ 2 嘅成語做錨**：避免由頭到尾都係冷僻成語、保證玩家有入手點。
- 200 關嘅成語組合＋模式全部唯一（基礎篇與進階篇之間都唔可以重複；正式資料 ≥688 條時；內部實作見 LEVEL_DESIGN）。
- 每關標題 `第 N 課：四字標題`、故事 1–2 句，唔可以穿橋提及本關任何答案成語。

## 5. 操作與互動

### 5.1 基本操作（滑鼠／觸控）

1. **點空格** → 該格高亮（選中）；如果該格已填字，再點一下／點字卡可以退回字庫（未鎖定前）。
2. **點字庫字卡** → 字卡放入目前選中嘅空格；字卡喺字庫變成「已用」狀態。
3. 玩家可以自由切換選中格、自由退回；**只有當一句所有格填滿先會自動判定**。
4. 判定正確 → 該句全部格變綠鎖定（包括交叉格），對應字卡正式消耗。
5. 判定錯誤 → 該句震動、清空該句玩家填入嘅字（字卡返回字庫）、`mistakes + 1`、貓貓傷心。
6. **重玩**：任何時間可以重玩本關（進度唔會倒退，重玩取最高星）。
7. **提示**：按提示鍵 → 隨機揭示一個未填空格（鎖定該字，`hintsUsed + 1`），提示次數有限。

### 5.2 鍵盤（桌面）

- `Tab` 喺格／字卡之間移動，`Enter`／`Space` 選取或放入。
- `Esc` 關閉 overlay（教學／章節故事／過關）；`R` 重玩（可選）。
- 所有可互動元素有清楚 focus ring；overlay 開啟時 focus trap 喺 overlay 內。

### 5.3 回饋（事件 → 視覺／音效）

| 事件 | 觸發時機 | UI 表現（概念） | 音效 |
| --- | --- | --- | --- |
| `place` | 放一張字卡 | 字卡飛入格、格閃一下 | `place` |
| `word-correct` | 一句填滿且正確 | 該句全部格變綠、鎖定、貓貓 happy、輕微彈跳 | `correct` |
| `word-wrong` | 一句填滿但錯誤 | 該句震動、紅閃、清空該句、貓貓 sad、mistakes 顯示 +1 | `wrong` |
| `hint` | 使用提示 | 該格金光揭示、鎖定、提示次數 -1、貓貓 think→happy | `hint` |
| `solved` | 全部成語鎖定 | 棋盤完成動效、彩紙、星星逐粒亮起 | `clear`＋`star`＋`fanfare` |

- 使用者第一次 pointerdown 時初始化音效（`audio.init()`）；音效開關跟 `save.settings.sound`。
- 尊重 `prefers-reduced-motion` 及設定內 `reducedMotion`：停用大動畫／彩紙，只保留必要狀態變化。

### 5.4 選中／退回細節

- 字庫字卡可以**先選卡再選格**，亦可以**先選格再選卡**（UI 兩種都支援較佳）。
- 已鎖定（given／correct／hint）嘅格唔可以再改。
- 錯誤清空時，如果某交叉格已經屬於另一句「已鎖定」嘅成語，唔會被清走（引擎兩階段鎖定，見 §6.2）。

## 6. 自動判定（引擎契約）

判定由 `src/core/puzzle.ts` 負責，UI 只依事件更新畫面。以下係玩法層面嘅規則整理。

### 6.1 遊戲狀態

- `GameState.cells`：每格 `{ char, locked, source: 'given' | 'word' | 'hint', bankIndex? }`。
- `GameState.words`：每個 slot 嘅狀態；`locked` 表示該成語已完成並鎖定。
- `mistakes`、`hintsUsed`、`solved`、`stars`。

### 6.2 判定流程

1. `createGame(level)`：
   - 由 `cells` 建立解答格；空格格清空，given 格顯示並鎖定。
   - `blanks = []` 嘅成語（即 chain row 0）**一開始就當已完成並鎖定**（引擎已支援）。
2. 玩家放字／用提示後，引擎只檢查「被 touched 嘅格所屬、尚未鎖定、而且所有格都已填滿」嘅成語。
3. **兩階段處理**（保證交叉格安全）：
   - 先鎖定所有判定正確嘅成語（格 locked、word locked、發 `word-correct`）。
   - 再處理錯誤成語：`mistakes + 1`、清空該句「玩家填入且未鎖定」嘅格（given／已鎖定格唔清）、發 `word-wrong`（附被清空嘅格 key）。
4. 每次判定後檢查是否全部成語 locked → `solved = true`、計算星級、發 `solved`。
5. 過關後所有操作失效（`placeChar`／`removeChar`／`useHint` 直接返回空）。

### 6.3 判定邊界情況

| 情況 | 規則 |
| --- | --- |
| 交叉格同時屬於兩句 | 該格只有一個答案字；兩句都填對先會分別鎖定；兩句都完成時一次／逐次事件處理皆可 |
| 錯誤句包含已鎖定格（另一句已對） | 清空時跳過已鎖定格；該格保留正解，唔會重複扣分 |
| 一句有多個空格 | 所有空格填滿先判定；中途唔會判定 |
| 提示字 | 鎖定（source=`hint`），玩家唔可以再改；提示字可以令句子完成並觸發判定 |
| chain row 0 全顯示 | 建立遊戲時已 locked，玩家只會填其餘行；全部行完成 → 過關 |
| 重玩 | 建立全新 `GameState`；存檔星星取最高、錯誤／提示次數取最少 |

### 6.4 事件契約（UI 依賴）

```ts
type GameEvent =
  | { type: 'place'; key: string; char: string }
  | { type: 'word-correct'; slotIndex: number; idiomId: string; cells: string[] }
  | { type: 'word-wrong'; slotIndex: number; idiomId: string; cells: string[]; mistakes: number }
  | { type: 'hint'; key: string; char: string }
  | { type: 'solved'; stars: number };
```

- UI 收到 `word-wrong` 要用 `cells` 把對應字卡放回字庫（`removeChar` 回傳 bankIndex，或由事件自行同步）。
- 提示回傳 `bankIndex`：UI 將該張字卡標記為已用；如果 `-1`，自行搵一張同字未用卡。

## 7. 提示系統

| 章 | 提示次數 `hintLimit` |
| --- | --- |
| 1–3 | 3 次 |
| 4–6 | 2 次 |
| 7–10 | 1 次 |

- 提示揭示一個**隨機未填嘅空格**嘅正解字，該格即時鎖定；每次 `hintsUsed + 1`。
- 提示唔會清除已填字、唔會扣 mistakes；用完 `hintLimit` 後提示鍵禁用（顯示剩餘 0 次）。
- 提示係同字庫卡連動：提示字會消耗一張對應字卡；如果字庫冇未用同字卡（UI 狀態不同步），引擎以解答為準，UI 自行對齊。
- 設計意圖：提示係「保底」而唔係主要策略——3 星要求零提示零錯誤；2 星容忍其中一項；1 星保底。
- UI 顯示：提示按鈕＋剩餘次數（`hint-btn`、`hint-count`）。

## 8. 星級、進度與解鎖

### 8.1 星級

| 條件 | 星數 |
| --- | --- |
| 0 錯誤、0 提示 | ★★★ |
| 錯誤／提示其中一項 > 0（另一項 = 0） | ★★ |
| 兩項都 > 0 | ★ |

- 最少 1 星；過關必得星。
- 重玩取歷史最高星；存檔同時保留最少 mistakes／hints（用於紀錄）。
- 星數用途：地圖每關星星、每章星星進度、總星數（`home-progress`／`map-stars-total`）。
- 錯誤定義：每次「一句填滿但錯」＝1 次 mistake（同一句重複填錯會累加）。
- 提示次數上限由關卡 `hintLimit` 決定，星級只看「有冇用過」而非用幾次。

### 8.2 進度與解鎖

- 自動儲存喺 `localStorage`（key 由 `core/progress.ts` 管理，`SAVE_VERSION` 版本化）。
- 解鎖規則：Level 1 自動解鎖；其餘關卡當「前一關已過關（≥1 星）」即解鎖。
- 首頁顯示「開始冒險」或「繼續第 N 關」（N = 最大已解鎖關卡）。
- 地圖顯示 **20 章**（基礎篇 10＋進階篇 10，可分兩段／自動 scroll）；每章 10 個關卡腳印：
  - 已過關：顯示星數（1–3）；
  - 當前可玩：閃動提示；
  - 未解鎖：鎖頭；
  - 章節按鈕顯示該章星數／10。
- 章節第一次進入顯示章節故事卡（`seenChapters`）；第一次玩 Level 1 顯示新手教學（`tutorialSeen`）。
- 結算 overlay：星星動畫、本關成語卡（拼音／釋義／出處／sourceBook／例句）、「下一關」「再玩一次」「返回地圖」。
- 收集：過關時把本關所有 `idiomId` 收入圖鑑（`recordLevelClear(..., idiomIds)`）；圖鑑顯示已收集詳情，未收集顯示「？」。
- 存檔異常（私密模式／容量不足／壞 JSON）→ 靜默使用預設存檔，遊戲照玩。

## 9. 章節、關卡節奏與 Boss 安排

### 9.1 章節節奏

- 每章 10 關：第 1–9 關一般關卡、第 10 關章末考驗（Boss）；第 2–10 章及第 11–20 章第 5 關係接龍挑戰。
- 章節內遞進：同一章由第 1 關到第 10 關，難度參數（空格數、tier、誘餌）隨關卡 id 線性上升。
- 章節之間遞進：成語數、空格比例、tier 每章遞增；提示次數每 3 章減 1；誘餌字每章增加。

### 9.2 每章結構

| 章 | 關卡 | 模式安排 | 章末（Boss） |
| --- | --- | --- | --- |
| 1 | 1–10 | 10 fill（教學） | Level 10：fill 章末考驗 |
| 2–9 | 每章 10 關 | 8 fill＋2 chain（第 5、10 關） | 第 10 關：chain 章末考驗 |
| 10 | 91–100 | 8 fill＋2 chain（第 5、10 關） | Level 100：chain 最終考驗（6 句） |

- Boss 關唔會突然加新機制，只係同一模式嘅最難組合＋專屬故事文案，保證公平。
- Level 1–3 教學節奏：
  - Level 1：2 句 fill、2 個空格（每句 1 格）、提示 3 次；配新手教學 overlay（點格→點卡→自動判定）。
  - Level 2：2 句 fill、2 個空格，換另一組交叉位置；教「交叉格兩句共用」。
  - Level 3：2 句 fill、2 個空格，開始有少少變化（方向／交叉位不同），完成教學期。
- 章節故事卡：第一次入章時顯示該章 blurb；玩家可以跳過，之後喺地圖點章節名可重看（可選）。

### 9.3 敘事文案規範

- 每關 `title`：`第 N 課：四字標題`，標題配合場景氣氛（例：`第 3 課：櫻語初開`、進階篇 `第 1 課：閣中尋卷`）；全 **200 個**標題唯一。
- 每關 `story`：1–2 句、20–60 字為目標；阿墨／糰子互動，交代情境或今次玩法重點；**唔可以包含本關任何答案成語**（生成器自動檢查）。
- 章末故事用「章末考驗」語氣；Level 100 用結局語氣（十個靈珠亮起）。
- 用字：繁體中文（香港用語）；唔用簡體字、唔用注音；成語本字要正字（由 idioms.json 提供）。

## 10. 數值曲線

### 10.1 難度參數（單一事實來源）

- 難度 `d = (id - 1) / 99`，由 0（Level 1）到 1（Level 100）。
- **fill 成語數** `n = 2 + round(2d)`，上限 4。
- **chain 接龍長度** `k = 3 + round(3d)`，上限 6。
- **目標空格比例** `r = 0.30 + 0.35d`（空格數 / 所有 slot 字數＝4 × 成語數）。
  - fill 目標空格數 `round(r × 4n)`（生成器會依幾何微調 ±1）。
  - chain 目標空格數 `clamp(round(r × 4k), k-1, 2k-1)`；因 §4.3 嘅 given 限制，chain 實際空格比例上限見 LEVEL_DESIGN。
- **提示次數**：基礎篇第 1–3 章 3 次、4–6 章 2 次、7–10 章 1 次；進階篇第 11–15 章 2 次、16–20 章 1 次。
- **誘餌字**：基礎篇每章 `0, 1, 1, 2, 3, 3, 4, 5, 5, 6`；進階篇 `6, 6, 7, 7, 8, 8, 9, 9, 10, 10`，並受字庫上限 ≤22 張約束（見 §19）。
- **成語 tier（fill）**：目標平均 tier `1.7 + 3.1d`（約 1.7 → 4.8）；每關至少 1 個 tier ≤ 2 錨；非錨成語後段優先 tier 3–5。
  - 因錨點一定係 tier ≤2，4 句 fill 嘅理論平均 tier 上限約 4.25；實測最終章節平均約 3.6–3.8（tier 4/5 佔 71–74%），符合「尾章 4/5 為主」。
- **成語 tier（chain）**：用溫和曲線 `2.6 + 1.4d`（約 2.6 → 4.0）。接龍要保留 tier ≤2 錨＋首尾相接，實際平均 tier 上限約 3.5；難度主要由接龍長度、誘餌、提示承擔。
- **進階篇（101–200）**：fill tier 目標 `3.8 → 4.6`、chain `3.9 → 4.6`；每關錨放寬到 tier ≤3；詳見 §19.3。

| --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | 1–10 | 2 | — | 0.250–0.375 | 3 | 0 | 1.70–1.98 |
| 2 | 11–20 | 2 | 3–4 | 0.333–0.375 | 3 | 1 | 2.01–2.29 |
| 3 | 21–30 | 2–3 | 4 | 0.375–0.417 | 3 | 1 | 2.33–2.61 |

| 6 | 51–60 | 3 | 5 | 0.450–0.500 | 2 | 3 | 3.27–3.55 |

### 10.3 難度設計理由

- **成語數遞增**：由 2 句（4×2 盤面）到 4 句（更多交叉、更多組合），資訊量同搜尋空間變大。
- **空格比例遞增**：早期每句只空 1 格、大量 given 提示；後期每句空 2–3 格，需要真正記住成語。
- **tier 遞增**：早期成語（畫蛇添足、守株待兔）屬小學常識；後期（運籌帷幄、曲突徙薪）較冷僻，配合圖鑑學習。接龍因連接限制用較溫和嘅 tier 曲線（難度由長度承擔）。
- **錨**：即使最難關都有一個 tier ≤2 成語，玩家可以由最熟悉嘅一句入手，避免「一句都唔識」嘅挫敗。
- **提示遞減**：由 3 次保底到 1 次，促使玩家記成語；3 星要零提示零錯誤，提供重玩動機。
- **誘餌字增加**：由零誘餌到 6 個誘餌，增加「揀錯卡」嘅判斷；誘餌字刻意唔等於任何空格答案字，避免一張卡永遠錯嘅不公平情況。

## 11. 字庫（bank）設計

- `bank` 係 **multiset（可重複字）**，內容＝〔所有空格所需字，逐格一張〕＋〔誘餌字〕。
- 排序：生成器用關卡 seed 洗牌，令同一關每次載入次序一致（可重現）。
- 誘餌字規則：
  - 誘餌字唔等於本關任何空格答案字（唔會同正解混淆／亦唔會多送一張正解卡）。
  - 誘餌字由全成語字庫抽，優先揀其他成語用字，令表面睇落合理。
  - 數量跟章節曲線（0 → 6）。
- 提示消耗字卡：提示字會佔用一張同字卡；UI 以 bankIndex 同步「已用」狀態。
- 玩家由字庫揀錯字 → 放入格後只會喺整句填滿時先判定；唔會即時彈錯，保留試錯空間。

### 12.1 畫面清單

1. **首頁 `#/home`**：貓貓 hero（阿墨＋糰子）、標題、主 CTA（開始冒險／繼續第 N 關）、圖鑑、設定、進度（總星數／已過關數）、櫻花背景。

3. **遊戲 `#/game/<id>`**：HUD（返回、關卡標題、提示＋剩餘次數、重玩、音效）；貓貓旁白／story；棋盤；字庫；chain 連接線。
4. **圖鑑 `#/codex`**：已收集成語列表、搜尋／篩選、詳情（成語、拼音、釋義、出處、sourceBook、例句）、收集進度。
5. **設定 `#/settings`**：音效、減少動態、重置進度（二次確認）、版本／credit。
6. **Overlay**：新手教學（Level 1 首次）、章節故事（每章首次）、過關結算、確認 modal、toast。

### 12.2 遊戲畫面佈局概念

- **手機（≤600px，單欄）**：上方 HUD → 貓貓 story 卡 → 棋盤（正方形格、自動縮放、唔好橫向 scroll）→ 字庫（底部 sticky，可換行，每張卡≥44×44 touch target）。
- **桌面（≥900px，雙欄）**：左欄貓貓插畫＋story＋提示；右欄棋盤＋字庫。
- **棋盤**：
  - 有字格：淺奶油底、深墨綠字、圓角；given 字稍淡、鎖定後成語整句變綠底；
  - 空格：虛線邊／淡粉底；選中：粉紅外框＋放大少少；
  - chain 關：每行左側顯示連接箭頭，上一行尾字與下一行首字之間畫連接線／光點；
  - 錯誤：整句 shake（reduced motion 時只紅閃）。
- **字庫**：卡片顯示單字；已用卡變暗／縮小；點擊後飛入格；鍵盤可操作。
- **過關 overlay**：星星逐粒亮起＋彩紙（reduced motion 停用）；成語卡縱向列表可捲動；主要 CTA「下一關」。
- **測試 id**：全部依 PLAN §7.4（`game-screen`、`cell-<r>-<c>`、`bank-<index>`、`hint-btn`、`result-overlay` 等），QA E2E 依賴。

### 12.3 首次使用流程

1. 首次開 App → 首頁（顯示「開始冒險」）。
2. 點開始 → `#/game/1` → 新手教學 overlay 3 步（選格、選卡、自動判定）→ 開始玩。
3. 完成後 close overlay → 地圖解鎖 Level 2。
4. 首次入第 2 章起每章顯示章節故事卡（可跳過）。

### 12.4 錯誤／邊界 UI

- 未解鎖關卡網址（`#/game/999` 或未解鎖）→ 引導返回地圖並 toast。
- 存檔壞／私密模式 → 照玩，只提示「進度未能儲存」。
- 音效未 init → 首次 pointerdown 初始化；被瀏覽器封鎖時靜默。
- 視窗太窄 → 唔好出現橫向 scroll；棋盤以 `min(vw, vh)` 控制大小。

## 15. 平衡與可玩性設計

1. **錨點優先**：每關開局至少有一句玩家可能識嘅成語；玩家可以由錨開始建立信心。
2. **交叉冗餘**：fill 關交叉格令兩句互相提供線索——一句填對可以幫另一句。
3. **試錯成本低**：錯只清空該句、不扣星（只影響星級），冇時間限制，唔會卡死。
4. **提示保底**：即使成語唔識，3 次提示（早期）足以完成；提示只影響星級。
5. **星星驅動重玩**：3 星需要零錯零提示；配合「重玩取最高星」，鼓勵重玩同一關。
6. **接龍難度主要靠長度**：chain 3–6 句完整階梯＋溫和 tier 曲線，避免「成語太冷僻」蓋過接龍樂趣。
6. **收集驅動**：圖鑑把成語變成收藏品；已收集成語可重看釋義／出處，形成學習閉環。
7. **節奏變化**：每章第 5、10 關轉接龍，避免 82 關填字單調；接龍保留首尾字令關係清晰。
8. **難度可見**：關卡標題、章節場景、HUD 剩餘提示、星數都令玩家知道「而家有幾難」。
9. **公平性**：誘餌字唔會同答案字重複；每句至少一個 given；chain 連接位必定顯示。
10. **可及性**：鍵盤、focus、aria、reduced motion、足夠 touch target、對比度。

### 19.2 進階篇玩法差異

| 項目 | 基礎篇（1–100） | 進階篇（101–200） |
| --- | --- | --- |
| 難度參數 | `d = (id-1)/99` | `d2 = (id-101)/99` |
| fill 成語數 | 2–4 | **4–5**（棋盤 ≤10×10，優先 ≤9×9） |
| chain 長度 | 3–6 | **6–7**（105–150 為 6、155–200 為 7） |
| fill 空格 | 每句 1–3 空格（每句最少 1 個 given） | 每句 **1–4** 空格；全關最少保留 2 個 given（部分成語可以全空） |
| 空格比例 | 0.30 → 0.65 | **0.60 → 0.72**（以 4×成語數為分母；公式 round 後實際 fill 0.625–0.70，章節平均因 chain 結構上限會更低） |
| 提示次數 | 3 → 1 | 第 11–15 章 **2**、16–20 章 **1** |
| 誘餌字 | 0 → 6 | **6 → 10**，但 bank 上限 **≤22 張**（空格多時誘餌實際減至 8–9） |
| 成語 tier | 1 → 4/5；每關錨 tier ≤2 | 以 tier 4/5 為主，平均目標 3.8 → 4.6；每關錨 **tier ≤3** |
| 成語來源 | 常用成語（tier 1–3 為主） | 加入 ≥200 條冷僻成語（tier 4/5 為主），題材更廣（自然／人物／哲理／動物…） |
| 章末 Boss | 每章第 10 關 | 每章第 10 關；Level 200＝最終考驗 |

- **引擎不變**：判定、提示、星級、事件、bank 用法完全一樣；UI 只需支援更大棋盤（最多 10×10）同更長字庫（最多 22 張卡）。
- **進度兼容**：Level 101 解鎖條件＝完成 Level 100；舊存檔（Level 1–100）可以直接繼續玩進階篇。
- **基礎篇凍結**：生成 200 關時，Level 1–100 直接沿用現有 `levels.json`（生成器讀入後原樣輸出），保證玩家已玩過嘅關卡、圖鑑、星數不變。

### 19.3 進階篇數值曲線

| 參數 | 公式 | 備註 |
| --- | --- | --- |
| `d2` | `(id-101)/99` | 0（Level 101）→ 1（Level 200） |
| fill 成語數 `n` | `4 + round(d2)` | 101–150：4；151–200：5 |
| chain 長度 `k` | `6 + round(d2)` | 105–150：6；155–200：7 |
| 目標空格比例 | `0.60 + 0.12 × d2` | 分母＝4×成語數；chain 上限 2k-1 |
| fill 目標空格數 | `round(比例 × 4n)`，clamp 至「格數−2」 | n=4 最多 11、n=5 最多 14 |
| chain 目標空格數 | `clamp(round(比例 × 4k), k-1, 2k-1)` | k=6 最多 11、k=7 最多 13 |
| 提示次數 | 章 11–15：2；16–20：1 | 新一章補回少少提示 |
| 誘餌字 | 章 11–20：`6,6,7,7,8,8,9,9,10,10` | bank = 空格＋誘餌 ≤22 → 實際誘餌可能被截 |
| fill tier 目標 | `3.8 + 0.8 × d2` | 3.8 → 4.6；每關錨 tier ≤3 |
| chain tier 目標 | `3.9 + 0.7 × d2` | 接龍連通＋錨限制，屬溫和曲線 |
