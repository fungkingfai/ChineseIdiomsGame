## 2. 設計原則

1. **曲線平滑、章內遞進**：難度 `d = (id-1)/99` 同時控制成語數、空格比例、tier、誘餌、提示，每章第 10 關最難。
2. **兩種模式交替**：第 1 章全 fill 教學；第 2–10 章每章第 5 關係接龍挑戰、第 10 關係章末（Boss），避免 82 關填字單調。
3. **每關可入手**：每關至少 1 個 tier ≤ 2 錨；fill 每句保留 1–3 格 given；chain 首行全顯示＋每行首尾字顯示。
4. **可解＋公平**：每句最少一個空格（引擎一定會判定）；bank multiset 一定夠字；誘餌字唔等於任何答案字。
5. **資料驅動**：所有數值由公式產生，唔手寫 100 關；改公式或 idioms 後重跑即可，結果可重現。
6. **驗證先於寫檔**：生成器內建獨立驗證；任何一項 fail 都唔會覆寫 `levels.json`。

## 3. 難度公式（單一事實來源）

`d = (id - 1) / 99`（Level 1 → 0、Level 100 → 1）

| 參數 | 公式 | 備註 |
| --- | --- | --- |
| fill 成語數 `n` | `min(4, 2 + round(2d))` | id 1–25：2；26–75：3；76–100：4（chain 關除外） |
| chain 長度 `k` | `min(6, 3 + round(3d))` | 15→3；20–50→4；55–80→5；85–100→6 |
| 目標空格比例 `r` | `0.30 + 0.35d` | 分母＝所有 slot 字數＝4 × 成語數（PLAN §4.4） |
| fill 目標空格數 | `round(r × 4n)` | 幾何／每句 1–3 空格限制下可能 ±1 |
| chain 目標空格數 | `clamp(round(r × 4k), k-1, 2k-1)` | 因 given 結構限制，實際比例上限＝2k-1 個空格 |
| 提示次數 | 章 1–3：3；4–6：2；7–10：1 | 每關 1–3 次（PLAN 要求） |
| 誘餌字 | 章 1–10：0,1,1,2,3,3,4,5,5,6 | 逐章不減、0 → 6 |
| tier 目標平均（fill） | `1.70 + 3.10d` | 取樣後 clamp 1–5；每關至少一個 tier ≤ 2 錨 |
| tier 目標平均（chain） | `2.60 + 1.40d` | 溫和曲線：接龍要保留 tier ≤2 錨＋首尾相接，實際平均 tier 上限約 3.5（見 §9.5） |
| 成語 tier 下限（非錨） | d>0.72 → tier ≥3；d>0.40 → tier ≥2 | 避免後段非錨成語跌返 tier 1 |

## 7. 教學關安排（Level 1–3）

教學目標：三分鐘內明白「點格 → 揀字卡 → 一句填滿自動判定 → 過關攞星」；唔好一次過教接龍。

| 關卡 | 成語數 | 空格 | 教學重點 | 預期玩家動作 |
| --- | --- | --- | --- | --- |

## 8. 章節尾／Boss 關安排

- **定義**：每章第 10 關（id % 10 === 0）＝章末考驗（Boss）；第 100 關＝最終考驗。

## 9. chain 關設計細節

### 9.1 幾何

- `rows = k`、`cols = 4`；第 i 行 `row=i, col=0, dir="h"`。
- 接龍條件：`word[i][3] === word[i+1][0]`（尾字＝下一句首字）；同行獨立、唔共用格。
- 視覺：行與行之間畫接龍連接線／箭頭，上一行尾字同下一行首字用同一顏色 highlight。

### 9.2 given／空格規則（固定）

| 行 | given | 可空格 index | 每行空格上限 |
| --- | --- | --- | --- |
| row 0 | 全 4 字 | —（`blanks=[]`，引擎自動鎖定） | 0 |
| row 1 … row k-2 | index 0、3 | 1、2 | 2 |
| row k-1 | index 0 | 1、2、3 | 3 |

### 9.3 每種長度嘅空格上限同實際分配

| k | 目標空格數（公式 clamp 後） | 實際比例上限 | 分配（row0 / 中段 / 尾行） |
| --- | --- | --- | --- |
| 3 | 4 | 4/12 = 0.333 | row1：2 格；row2：2 格 |
| 4 | 6–7 | 7/16 = 0.438 | row1–2：各 2 格；row3：2–3 格 |
| 5 | 9 | 9/20 = 0.450 | row1–3：各 2 格；row4：3 格 |
| 6 | 11 | 11/24 = 0.458 | row1–4：各 2 格；row5：3 格 |

- 生成器按公式 target 分配（最少每行 1 個空格，上限見上表），並用 level seed 決定邊幾格空。
- chain 關嘅「空格比例」天然低於同章 fill，係因為接龍連接位必須顯示；難度遞增改由成語數、tier、誘餌、提示次數承擔（見 §3）。

### 9.4 接龍資料依賴

- 生成器先計算「全資料庫可達最長接龍長度」`maxChainLength`（上限 6）；只有資料未夠時先會縮短 k（最少 3）。
- 最終 488 條資料：174 筆可接龍、578 條鏈接、最長 37 步，`maxChainLength = 6`；18 關接龍全部按 §4.2 用 k=3/4/5/6，**零 fallback**。
- 唯一性：`findChainPath` 以多起點 DFS＋tier 排序搜尋，並避開前面關卡已用嘅成語組合；18 關 strict 唯一 PASS。

### 9.5 chain 關嘅 tier 目標（溫和曲線）

- 接龍每關必須保留一個 tier ≤2 錨，而且下一句首字要等於上一句尾字，所以平均 tier 有結構上限：實測最佳 k=6 鏈平均約 3.5（理論上 tier2 錨＋五個 tier5 = 4.5，但真實接龍圖達唔到）。
- 因此 chain 關用**溫和 tier 曲線** `2.60 + 1.40d`（約 2.6 → 4.0），唔用 fill 關嘅嚴格 tier 閘；接龍難度主要由長度 k、誘餌字、提示次數承擔。
- 生成器以「k 完整階梯優先」：唔會為咗平均 tier 而縮短接龍長度；搜尋時用多起點＋tier 排序盡量揀高 tier，但唔會出 fallback 警告。
- 實測（488 條）：18 關 chain 平均 tier 2.40–3.17、全部有 tier ≤2 錨；章節整體 tier 由 fill 主導（第 9–10 章 tier 4/5 佔 71–74%）。

## 10. fill 關設計細節

### 10.1 幾何生成規則

1. 第一個成語（錨，tier ≤ 2）放喺 `(0,0)`，方向隨機 `h`／`v`。
2. 每個新成語必須同「現有棋盤」共用**剛好 1 格**（strict 模式）：該格答案字一致；重疊 0 格（唔交叉）或 2 格以上（奇怪重疊）都拒絕。
3. 盤面必須橫直混合（唔可以有 1×7／7×1 直線盤面）。
4. 盤面 bounding box 上限 9×9；資料不足時 fallback 放寬到 11×11／容許 1–3 格重疊（仍要字字一致）。
5. 成語不得重複使用（同一關內每句不同）；每個成語只計一次。
6. 交叉結構形成連通圖：第 1 句→第 2 句→…→第 n 句，每個新句都同前面至少一句相連。

### 10.2 given／空格生成規則

1. 目標空格數 `T = round(r × 4n)`（可能 ±1 微調）。
2. 先揀「given 格」集合 `G`（|G| = 總格數 − T），要求：
   - 每個 slot 至少 1 個 given（避免全句空白、保持可讀性）；
   - 每個 slot 最多 3 個 given（即每句最少 1 個空格，引擎一定會觸發判定）；
   - `G` 要覆蓋所有 slot（set cover；優先揀交叉格，因為一格可以同時做兩句嘅 given）。
3. 其餘格＝空格；空格字即 bank 內容（去重格計一次）。
4. 驗證：每句空格數 1–3；bank multiset 足夠；空格比例符合公式 ±1。

### 10.3 盤面大小

| 成語數 | 去重格數（典型） | 典型盤面 |
| --- | --- | --- |
| 2 | 7 | 4×4 十字 |
| 3 | 10 | 5×4 ~ 7×5 |
| 4 | 13 | 5×6 ~ 7×7 |

- 上限 9×9（避免手機棋盤太細）；極端 fallback 11×11。
- 交叉格在 `cells` 只出現一次，解答字唯一。

### 10.4 例子（Level 1 教學關，最終資料）

```text
風花雪[月]   ← 橫向 slot：風花雪月，blanks=[3]（填「月」）
· ·[中]·    ← 直向 slot：雪中送炭（row0,col2 起），blanks=[1]（填「中」）
· · 送 ·
· · 炭 ·
```

- 兩句於「雪」交叉；bank＝`["中","月"]`（2 空格、0 誘餌）。
- 玩家只需放 2 張卡，配合新手教學。

## 11. 誘餌字、bank 與提示策略

- **bank 數量**＝空格格數（去重）＋章節誘餌字數；數量同 multiset 檢查由生成器內建驗證。
- **誘餌字**：
  - 由全成語字庫抽，**排除本關所有空格答案字**（避免混淆／避免多送正解卡）。
  - 每章數量固定跟曲線；生成器用 level seed 洗牌字庫次序。
  - 早期 0 誘餌（專心學規則）；後期 6 誘餌（要由字卡中辨認）。
- **提示**：每關 `hintLimit` 1–3；提示隨機揭示一個未填空格，鎖定該字；提示愈少＝章節愈後。
- **公平性**：誘餌唔同答案重複、每句最少一個 given、chain 首尾字必顯示、每關有 tier ≤2 錨。

## 12. 生成算法（`scripts/generate-levels.mjs`）

### 12.1 輸入／輸出

| 項目 | 內容 |
| --- | --- |
| 輸入 | `src/data/idioms.json`（≥420 條最終）、`src/data/chapters.json`（10 章） |
| 輸出 | `src/data/levels.json`（100 關，2-space JSON，UTF-8） |
| 指令 | `npm run generate:levels`＝`node scripts/generate-levels.mjs` |
| 額外選項 | `--dry-run`（驗證唔寫檔）、`--stats`（文字統計）、`--stats=json`、`--stats=md`、`--levels=N --out=/tmp/x.json`（小規模測試）、`--idioms=`／`--chapters=`（測試其他資料） |

### 12.2 Deterministic RNG

- 用 **mulberry32**；seed 由 `id`、重試次數 `attempt`、`salt` 經 FNV-1a 混合：`seedForLevel(id, attempt, salt)`。
- 同一份 `idioms.json`＋`chapters.json`＋salt → 兩次執行輸出**逐位元組相同**（已用 `cmp` 驗證；亦係驗收要求）。
- 生成順序固定 id 1→100；usage 統計由頭累積，所以結果穩定。
- 遊戲中「提示」用 `Math.random()`（玩法層，不需可重現），生成層完全唔用 `Math.random()`。

### 12.3 生成流程（每關）

```text
for id = 1..100:
  mode = (id >= 11 && id % 5 === 0) ? 'chain' : 'fill'
  for attempt = 0..MAX_LEVEL_ATTEMPTS:
    rng = mulberry32(seedForLevel(id, attempt, salt))
    if mode == 'fill':
      1. 幾何：錨（tier <= 2）→ 逐句揀交叉候選（按 tier 目標＋usage 排序，最多試 120 個）
         → 驗證單格交叉／字一致／橫直混合／盤面 <= 9x9
      2. 品質閘：平均 tier 要接近目標（後段另要求 >= 2 個 tier 4/5），否則換幾何
      3. 空格：set cover 揀 given（每句 1-3 空格）→ 達唔到就先後試 T、T+1、T-1、T+2
      4. bank：空格字 multiset ＋章節誘餌字（排除答案字）→ 洗牌
    else:
      1. 計算可用 k = min(公式 k, maxChainLength)（資料不足自動縮短，最少 3）
      2. 錨（tier <= 2）做起點 → 隨機化 DFS 搵接龍路徑（尾字＝首字；每句不重複）
      3. 每行分配空格（row0=0；中段首尾字保留、最多 2 空格；尾行首字保留、最多 3 空格）
      4. bank 同上
    5. 組裝 Level（id/chapter/mode/title/story/rows/cols/cells/slots/bank/hintLimit）
    6. 唯一性：signature = mode + 排序後 idiom ids；重複就換 seed 重試
    → 成功則記錄該關；usage[idiomId] += 1
  若 40 次外層重試都失敗 → 拋錯（唔寫檔）
```

### 12.4 成語 tier 選擇

- 每關第一個成語（錨）一定由 tier 1／2 揀；早期優先 tier 1、後期優先 tier 2。
- **fill 關**：其餘成語按「目標平均 tier」（`1.7 + 3.1d`）抽樣，帶抖動＋後段下限（d>0.4 → ≥2；d>0.72 → ≥3）；候選排序 `|tier − target| × 2.6 + usage × 0.22 + 隨機`；幾何平均 tier 離目標太遠會換幾何，真係做唔到先用「最佳 tier 平均」幾何 + 警告。
- **chain 關**：用溫和目標 `2.6 + 1.4d`（§9.5）；DFS 揀下一句時按 `|tier − target|` 排序＋隨機抖動；**唔會**用 tier 閘門去縮短 k（k 完整階梯優先），亦唔會因此出 fallback 警告。
- 兩者都用 usage 排序（用少嘅成語優先），保持全庫使用平均；每關至少一個 tier ≤2 錨。

### 12.5 唯一性與重試

- `signature = mode + "|" + 排序後 idiomIds`，全域 Set 追蹤；重複就換 attempt（新 seed）重試。
- 正式資料（≥420、連通性足）下，100 關全部 strict 唯一。
- 資料不足（interim）時：外層重試 10 次仍重複，先接受「內容唔同但組合重複」嘅關卡（full-JSON 仍要唯一），並記警告＋喺驗證報告標明；最終資料重跑後警告應清零。

### 12.6 Fallback 階梯

| 情況 | Fallback |
| --- | --- |
| 幾何放唔落／盤面太大 | 先放寬到 11×11、容許 1–3 格重疊（字仍要一致）；再換 anchor／換 seed |
| 目標空格數做唔到 | 試 T±1、T+2；每句仍保持 1–3 空格 |
| fill tier 達唔到目標 | 用「最佳 tier 平均」幾何做 fallback + 警告 |
| chain tier 達唔到溫和目標 | 接受最佳路徑（唔縮短 k、唔出警告）；最終 488 條零觸發 |
| 接龍長度不足 | `min(公式 k, maxChainLength)`；只有完全搵唔到目標長度路徑先縮短（最少 3）＋警告。最終 488 條零觸發 |
| 接龍組合重複 | 生成器搜尋時主動避開已用成語組合；真係資料不足先接受 full-JSON 唯一嘅關卡 + 警告（最終 488 條零觸發） |
| 成語數不足 | 生成器直接報錯（預設 100 關最少 60 條；`--levels=N` 測試最少 6 條），唔會寫壞檔 |

### 12.7 標題／故事

- 標題由固定 10 章 × 10 個四字標題表產生：`第 {章內第幾} 課：{標題}`；100 個標題固定、唯一、同 idioms 資料無關。
- 故事由每章 3 個 fill＋3 個 chain 版本＋章末／最終專屬故事組成，配合場景氣氛；生成器驗證「故事／標題唔包含本關答案成語」。
- Level 100 用 `FINAL_STORY`；章末（id%10===0）用 `BOSS_STORIES`。

### 12.8 CLI 行為

- 預設生成 100 關 → 寫入 `src/data/levels.json`；驗證 fail 一律**唔寫檔**並以 exit code 1 結束。
- `--stats` 輸出每章／逐關統計（可直接貼入本文件）；`--stats=md` 輸出 Markdown 表。
- `--dry-run` 可以做 CI／review 用；`--levels=N` 需要配 `--out=`，避免誤覆寫正式檔。
